# Operating_Platforms
CS-230 Operating Platforms
# Briefly summarize The Gaming Room client and their software requirements. Who was the client? What type of software did they want you to design?
The Gaming Room is game software company who was looking to expand the horizon on their existing game Draw it or Lose it by making it compatible and available for multiple operating systems. They required a game that can run on multiple types of clients but maintain one set of records on a server that maintain multiple player accounts with unique team and game names; new names would be checked for pre-existence. Although the game can support a great number of players accessing it at the same time, each separate group of players would be aware of one game session at a time.
#	What did you do particularly well in developing this documentation?
In developing this documentation, I believe that I have extensively explored the difference between the most common operating system in use today; especially on the server side which I discovered is mostly run by Linux. I became exposed with a multitude of tools that are available for developing software for sever connectivity, accessing databases. I was very informative in my recommendations of various aspects of the process of deploying a distributed software.
#	What about the process of working through a design document did you find helpful when developing the code?
In the process of working through the design document, I found helpful to have access to so much information from the official operating system’s websites, their user manuals and even actual installation files and instructions to test them if desired.
#	If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?
I would definitely improve my research on user requirements; I missed the fact that we did not have access to actual customers to interview and obtain feedback from given the settings of this exercise. We had to mostly work with the requirements we could think of or were built in the exercise.
#	How did you interpret the user’s needs and implement them into your software design? Why is it so important to consider the user’s needs when designing?
The user’s needs are the primary reason for the project in the first place; so, I consider it a failure if they are not met. With that in mind, every decision of what language to use, what platform to develop for, and what to include in the interface were all made to serve those needs. I also am of the mindset that if the customer gets what they need, they will not mind paying for it.
#	How did you approach designing software? What techniques or strategies would you use in the future to analyze and design a similar software application?
Designing software, like everything else, is best broken down into manageable phases: researching, planning, testing, documenting. When it comes to the coding part, small, independent modules that can be repurposed is my preferred approach; that serves my divide-and-conquer mentality well.
